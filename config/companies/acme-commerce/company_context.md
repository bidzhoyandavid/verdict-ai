## Продукт

Acme Commerce разрабатывает AI-агента для анализа A/B-тестов: пользователь загружает данные теста (метрики, группы) через чат в Streamlit, агент проводит статистический анализ и выдаёт вывод — победитель / не значимо / нужно больше данных. Вся статистика выполняется собственным пакетом abex (профилирование данных, проверка SRM, подбор теста, расчёт эффекта, guardrail-проверки, отчёт); агент на LangGraph/LangChain выступает только оркестратором поверх abex и не считает статистику самостоятельно. Граф включает обязательные этапы: загрузка и валидация данных, профилирование метрики, проверку SRM (alpha=0.001) как гейт перед выводом о значимости, автоматический подбор статметода через selector, расчёт эффекта и guardrail-проверок, поправку на множественные сравнения при нескольких метриках, и финальную интерпретацию в Insight Node. Часть функциональности пакета (байесовский анализ, sequential-тестирование, CUPED, детекция novelty-эффекта, разбивка по сегментам) — заглушки, не реализованы, и агент должен явно сообщать об этом пользователю, а не подменять их своими расчётами. Модель компании (B2B/B2C) не указана.

## Ключевые метрики

Конкретные ключевые бизнес-метрики компании не указаны в форме. Известно, что система рассчитана на работу с метриками разных типов, которые определяются через профилирование (в том числе ratio-метрики с линеаризацией, конверсионные/пропорциональные метрики) и с отдельными guardrail-метриками (упомянуты как пример latency, errors), которые проверяются параллельно с основной метрикой теста. Какие именно метрики являются целевыми и какие — guardrail для Acme Commerce, не указано.

## Специфика домена

Данных о сезонности бизнеса, длительности цикла принятия решений и регуляторных ограничениях не предоставлено — не указано. Из технической специфики, влияющей на интерпретацию результатов A/B-тестов, зафиксировано следующее: при обнаружении SRM (sample ratio mismatch) эксперимент считается невалидным и дальнейший расчёт значимости не производится; при наличии более одной метрики обязательна поправка Бонферрони на множественные сравнения перед выводом о значимости; effect size всегда сопровождает p-value, вывод не делается только на основании значимости; нарушение guardrail-метрики отражается в выводе агента даже при значимом положительном эффекте по основной метрике. Строгий контроль peeking-эффекта и novelty-эффекта пока не реализован в пакете — агент может дать только текстовое эвристическое предупреждение (если есть timestamp и тест короче ~1–2 недель), без строгого статистического расчёта, что следует учитывать при интерпретации результатов коротких тестов.
